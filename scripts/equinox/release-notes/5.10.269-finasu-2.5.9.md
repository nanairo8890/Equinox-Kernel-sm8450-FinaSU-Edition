# Equinox FinaSU Edition 2.5.9
Equinox Kernel by **[LF52406](https://github.com/LF52406)** for the POCO F5 Pro / Redmi K60 (`mondrian`),
FinaSU edition by **Nanairo8890** with LF52406's permission
FinaSU goes to **v1.7.1** and SELinux Hide is on by default, with the ROM's ADB root types hidden from apps. NoMount, SUSFS, the installer and everything else are the same as 2.5.8
## Files
- `Equinox-5.10.269-FinaSU-2.5.9-mondrian.zip`: AnyKernel3 zip. Flash it from a recovery or a kernel
  flasher; it checks the ROM's vendor modules and then replaces only the kernel `Image`, keeping the
  ROM's ramdisk, header and bootconfig
- `Equinox-5.10.269-FinaSU-2.5.9-mondrian-checkonly.zip`: the same package, named so that it only runs
  the check and flashes nothing. Use it to find out whether your ROM is compatible
- `FinaSU_v1.7.1_33227-release.apk`: the official FinaSU manager (`me.yuki.fina`), from FinaSU's release
  It updates earlier FinaSU managers in place
- `CHANGELOG.en.txt`, `CHANGELOG.es.txt`, `CHANGELOG.pt-BR.txt`, `CHANGELOG.ru.txt`: full changelog
## Before flashing
- Back up your `boot` partition first
- If you update your ROM, flash the zip again afterwards, because the ROM ships its own kernel
- Update the FinaSU manager to `v1.7.1` and let it update `ksud`
- Choose **NoMount** as the mount backend in the FinaSU manager. If you had the NoMount metamodule
  installed, remove it
## What 2.5.9 adds

- **FinaSU `v1.7.1`** (`1627e52f`, version 33227), up from `v1.7.0`; still UAPI 6. Use the `v1.7.1` manager
- Nothing changes in the kernel: v1.7.1 only touches the manager (the picker of apps excluded from NoMount) and `ksud` (it no longer extracts again at boot binaries that already exist, and it validates the module ID before cleaning its configuration). The kernel driver is the same as in v1.7.0; only the version it reports changes (from 33224 to 33227)
- **SELinux Hide by default**: the kernel turns it on shortly after boot, so an app can no longer check that the `ksu` contexts exist; a saved `selinux_hide=0` is respected
- The ROM's `adbroot`/`adbroot_exec` types are registered in the SUSFS hidden type list, so an app's selinuxfs queries no longer confirm them, while the ROM's real ADB root keeps working
- None of this touches FinaSU's official code
- The installer shows FinaSU v1.7.1 (33227)
- Same NoMount v2.3.1, Tracepoint hooks, SUSFS v2.4.0, BBR, DroidSpaces, `/proc/kallsyms` filter and installer

## If you use BRENE

- Do not configure SUSFS from the FinaSU manager while you use BRENE: both write the same settings
- BRENE applies `su_compat`, `kernel_umount` and `selinux_hide` on every boot; change them from its WebUI
- A `uname -r` with a double hyphen (`5.10.269--N-g...`) comes from BRENE's uname spoofing, which cannot
  find a KMI value in this kernel. Set a custom uname in BRENE

## Compatible ROMs

2.5.9 exports the same symbol CRCs as 2.0, 2.0.1 and 2.1, so the same ROMs are compatible:

- **Compatible:** MistOS 5.1 Beta (20261011 to 20261025) and MistOS 5.0 Alpha 20260914; the latest builds
  from Keosh with the kernel `5.10.269-gki-g1598dc02ea84`: crDroid 12.12 (20260928), Evolution X 11.11,
  Infinity-X 3.12 (VANILLA, GAPPS core and extra), Lunaris 3.12 (VANILLA and GMS), LineageOS 23.2
  (20260929) and Axion 2.8 (VANILLA and GMS); Infinity-X 4.1 by LF5 (17.10.2026); crDroid 12.12 by Taha
  Keles (20260930)
- **Not compatible:** AOSPA calcite and PenguinOS celerity. They use their own kernel
  (`5.10.269-beryl-7156c6f9fb`) and the installer stops on them

## Checks

- Tested on the phone (POCO F5 Pro, MistOS 5.1 Beta 20261025) after flashing to boot_a and rebooting: the kernel reports version 33227, `ksud` is 1.7.1 with UAPI 6, 0 modules rejected, SELinux is Enforcing, NoMount 23 (785), SUSFS v2.4.0 is initialized, and `dmesg` shows no Oops or panic
- KMI against clean Equinox: 0 changed CRCs and 0 removed symbols (only `put_pid_ns` is added)
- Vendor module CRCs OK (337 from `vendor_boot` and 390 from `vendor_dlkm`) for MistOS 5.1 Beta 20261025 and the 11 latest Keosh builds; AOSPA and PenguinOS are still not compatible
- The build shows no warnings or errors in the FinaSU, SUSFS and NoMount code
- The `/proc/kallsyms` filter leaves no driver symbol that reveals root
